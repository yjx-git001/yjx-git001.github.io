最快上手方式

1

安装 CLI

用 npm 或 Homebrew 直接安装，尽量保持环境简单干净。

2

完成登录

默认走 ChatGPT 登录；远程环境可使用 device auth。

3

登录状态一般会写入系统凭据库或 ~/.codex/auth.json。公开页面里只保留占位符，不放真实密钥。
02 · Config

配置与模型

这一节改成更像高级产品文档的“策略层 + 实际配置”双栏展示：左边直接给出可复制配置，右边解释优先级和模型选择逻辑，让页面既好看又实用。

用户级默认配置

~/.codex/config.toml 
model = "gpt-5.4"
model_reasoning_effort = "high"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
cli_auth_credentials_store = "keyring"
项目级覆盖放在仓库内的 .codex/config.toml；CLI flags 和 --config 优先级最高，其次才是 profile、项目级、用户级。

推荐模型

  • gpt-5.4：优先推荐，兼顾编码、推理和 agent 工作流。
  • gpt-5.4-mini：更快更省，适合轻量任务或 subagents。
  • gpt-5.3-codex-spark：更偏实时迭代；复杂工程也可考虑 gpt-5.3-codex。

临时切换方式

新开线程时直接用 codex -m gpt-5.4。正在进行中的会话，可以用 /model 快速切换，而不必改动默认配置。

项目信任机制

如果项目没有被信任，Codex 会跳过项目级 .codex/ 配置。因此“配置写了但没生效”时，优先检查项目信任状态。

04 · Proxy Layer

CCSwitch 配置

这一节重新做成更高级的标签切换面板，减少原先“普通文档块”的观感。请求地址继续保持为 https://yjxapi-gpt.xyz/v1，真实密钥仍然只用占位符演示。

~/.codex/config.toml
CCSwitch macOS / Linux 
model_provider = "OpenAI"
model = "gpt-5.4"
review_model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
network_access = "enabled"
windows_wsl_setup_acknowledged = true
model_context_window = 1000000
model_auto_compact_token_limit = 900000

[model_providers.OpenAI]
name = "OpenAI"
base_url = "https://yjxapi-gpt.xyz/v1"
wire_api = "responses"
requires_openai_auth = true
~/.codex/auth.json
Auth Example 
{
  "OPENAI_API_KEY": "sk-你的密钥"
}
%userprofile%\.codex\config.toml
